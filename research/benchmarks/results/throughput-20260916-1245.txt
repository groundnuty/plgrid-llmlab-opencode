PLGrid Forge throughput, 2026-09-16 ~12:45 CEST, host grzankax1 (lightly loaded gateway)

Method: streaming chat completions of one fixed prompt ("Write a Python function that
reverses a linked list iteratively. Code only, no explanation."), temperature 0, with
min_tokens = max_tokens = 300, so every completion is exactly 300 output tokens.
3 consecutive requests per model; the table shows medians.
  ttft   = time to first streamed token (s)
  total  = total wall time (s)
  naive  = tokens / total wall time (tok/s)
  decode = generation rate from first to last streamed token (tok/s) - the "tok/s"
           quoted in the docs, and the same quantity gateway.py reports as tok/s
  runs(decode) = the three individual generation rates

Produced by a scratch script equivalent to `gateway.py throughput --repeats 3`, except
that each model's three requests ran back to back rather than interleaved across models.

Load matters: the same measurement at 14:16 the same day, under heavy gateway load
(bench-20260916-141623.txt), gave rates roughly 2-8x lower, ranges such as 13-60 tok/s, and
time to first token up to 8 s. Treat these figures as best-case.
